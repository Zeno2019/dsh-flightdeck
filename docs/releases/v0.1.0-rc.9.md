# DSH Flightdeck v0.1.0-rc.9

## English

**RC.9 is a prerelease, not a stable release.** It is the next controlled candidate after RC.8. Do not treat this release as evidence that the first stable release or the RC.8 → RC.9 upgrade path has been completed.

### Version and compatibility matrix

| Component | Version / target |
|---|---|
| DSH Flightdeck | `0.1.0-rc.9` |
| Bundled DSH core | `0.1.0-rc.7` |
| Bundled `pnpm` | `11.8.0` |
| Windows package | x64 NSIS installer |
| macOS package | arm64 DMG (Apple Silicon) |
| `dshmarket` | `1.14.1` |
| `dsh-find-plugin` | `0.3.7` |
| `dsh-anchored-subagent` | `0.3.0` (`31fdd22a4265aef3107d9fca05854bea78a9af10`) |

The exact assets are:

- `dsh-flightdeck-0.1.0-rc.9-dsh-0.1.0-rc.7-windows-x64-setup.exe`
- `dsh-flightdeck-0.1.0-rc.9-dsh-0.1.0-rc.7-mac-arm64.dmg`

Flightdeck's local UI endpoint uses loopback. DSH itself, model providers, the plugin marketplace, and installed plugins may make network requests.

### Security and release mechanics

- The bundled `pnpm` is upgraded from `11.7.0` to exact `11.8.0` to address the high-severity `GHSA-qrv3-253h-g69c` path-traversal advisory affecting `>=11.0.0 <11.8.0`.
- The package embeds the pinned `pnpm` so marketplace tooling can work without a system Node/npm/Corepack/pnpm installation. Production dependency audit and the vendored launcher checks are part of the release gates.
- A tag matching `package.json` derives the version, DSH version, exact asset names, and `docs/releases/<tag>.md`. The Windows job builds and smoke-tests first, then creates or updates a **Draft** release with these notes and the Windows asset. The macOS job builds and smoke-tests the arm64 DMG, uploads it to the same Draft, verifies both exact assets, and only then publishes.
- These packages are unsigned. Windows has no Authenticode signature, so SmartScreen may warn; use **More info → Run anyway** only after verifying the downloaded asset. macOS has no Developer ID signature and no notarization, so Gatekeeper may block the first launch; use Finder's app-specific **Open** action or **System Settings → Privacy & Security → Open Anyway**. A targeted quarantine removal for this app is `xattr -d com.apple.quarantine /Applications/DSH\ Flightdeck.app`. Do not disable Gatekeeper globally.

### Validation boundary

The automated gates cover installation/unpacking, packaged-file and dependency-closure checks, application startup, DSH HTTP readiness on loopback, fatal-log markers, and process cleanup on Windows x64 and macOS arm64. They do not certify every plugin feature, model provider, network/proxy condition, antivirus product, user-managed plugin, or operating-system environment.

The RC.8 → RC.9 real upgrade and end-user flow (preserved sessions/settings/profile, real prompt and tool use, marketplace install, restart, and uninstall/reinstall behavior) remains **pending post-release manual acceptance** from the GitHub-downloaded assets. It must not be described as completed before that acceptance.

### 安全升级与发布机制

- 内置 `pnpm` 从 `11.7.0` 升级为精确 pin 的 `11.8.0`,处理影响 `>=11.0.0 <11.8.0` 的高危 `GHSA-qrv3-253h-g69c` 路径穿越漏洞。
- 应用内置该 pin 版本的 `pnpm`,因此在系统没有 Node/npm/Corepack/pnpm 时,插件市场仍可使用其工具链。发布门禁包含 production dependency audit 与 vendored launcher 检查。
- 与 `package.json` 一致的 tag 会动态推导版本、DSH 版本、精确资产名和 `docs/releases/<tag>.md`。Windows job 先构建并 smoke,再用 notes 创建或更新 **Draft** Release 并上传 Windows 资产。macOS job 构建并 smoke arm64 DMG,上传到同一个 Draft,核对两个精确资产后才 publish。
- 安装包均未签名。Windows 没有 Authenticode 签名,SmartScreen 可能警告;确认资产来源后使用「更多信息 → 仍要运行」。macOS 没有 Developer ID 签名和 notarization,Gatekeeper 可能拦截首次启动;对应用使用 Finder 的「打开」,或到「系统设置 → 隐私与安全性」对该应用选择「仍要打开」。也可只针对本应用执行 `xattr -d com.apple.quarantine /Applications/DSH\ Flightdeck.app`。不要全局关闭 Gatekeeper。

### 验证边界

自动化门禁覆盖 Windows x64 与 macOS arm64 的安装/解包、打包文件和依赖闭包检查、应用启动、loopback 上 DSH HTTP readiness、fatal log 标记和进程清理。不代表所有插件功能、模型 provider、网络/代理条件、杀毒软件、用户自管插件或所有系统环境都已认证。

RC.8 → RC.9 的真实升级与终端用户流程(会话/设置/profile 保留、真实 prompt 与 tool、从市场安装插件、重启以及卸载/重装行为)仍**等待发布后使用 GitHub 下载资产进行手工验收**。在验收前不得宣称该流程已完成。
